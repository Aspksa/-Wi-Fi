# Aspksa Wi-Fi v3.0 · Beacon / roaming / offline capture

Все функции работают в текущем портативном проекте Windows PowerShell 5.1 + C# + SQLite + браузер. Никаких изменений роутера или драйвера.

## Реализовано
1. **Свой Beacon IE Decoder:** ограниченный разбор сырых IE из уже доступных WLAN_BSS_ENTRY: HT, VHT, HE, EHT, RSN, P2P vendor IE и контроль повреждённых/обрезанных записей. Метки относятся только к возможностям, *объявленным точкой доступа*, а не к реальной скорости или согласованному режиму ноутбука.
2. **Wi-Fi 6/7:** HE capabilities/operation (IE extension 35/36), EHT operation/capabilities (106/108); используется имеющийся декодер HT/VHT/EHT ширины и вторичных сегментов. Неизвестные поля не угадываются. Радиозапись может быть недоступна драйверу или содержать устаревшие данные.
3. **Скрытые сети:** пустые SSID обозначаются как скрытые. Группировка по известному BSSID, без попыток раскрытия SSID и без deauthentication.
4. **Wi-Fi Direct:** подсчёт *локальных* виртуальных Wi-Fi Direct адаптеров через штатный Windows CIM. P2P IE в BSS выделяется отдельно. Это **не** сканирование списка соседних Direct-устройств: для него нужна подтверждённая поддержка соответствующего WinRT API и разрешений. Без такой поддержки панель честно сообщает, что поиск недоступен.
5. **Карта каналов:** без переписывания старого алгоритма отображает измеренные параметры 20/40/80/160 МГц и вторичные сегменты через `Get-SignalFootprint`, с указанием источника геометрии. Unsupported 6 GHz не выдумывается.
6. **Рейтинг сигналов:** сохранён существующий signal/RSSI ranking без превращения его в придуманную загрузку радиоэфира.
7. **Роуминг:** смена подключённого BSSID при том же SSID отмечается только по подтверждённому сканированию. Отдельно считаются локальные задержки/потери за последние 30 секунд, но причинность не утверждается.
8. **Диагностика:** v2.5 уже предоставляет версию драйвера через CIM при наличии данных; v3 добавляет локальное обнаружение P2P виртуальных интерфейсов и статуса службы Npcap. События WLAN AutoConfig за последние 12 часов читаются только для просмотра (до 8 записей с ID и временем, без текста возможных персональных сведений). При отсутствии прав данные помечаются как недоступные. Прямое декодирование NDIS/радиодрайвера не заявляется.
9. **Повторы:** сохраняется проверка BSSID SeenAt и независимых завершённых сканов из v2.5.
10. **Свой офлайн-PCAP:** безопасное чтение обычных PCAP с LINKTYPE_IEEE802_11 (105) и LINKTYPE_IEEE802_11_RADIOTAP (127). Только Beacon и Probe Response; предел 128 МБ, 3000 записей по умолчанию, 500 извлечённых кадров. Повреждённые кадры исключаются. PCAPNG и другие LinkType отклоняются. Не выводит RSSI или эфирную загрузку без аппаратных сведений.
11. **Monitor Capture:** пока только read-only проверка наличия Npcap. Наличие службы **не доказывает** совместимость драйвера с monitor mode. Живой радиозахват намеренно выключен, пока не подтверждён адаптер и разрешение.
12. **Автоисследование:** формирует осторожные гипотезы о EHT сетях, нестабильности и сочетании плотности соседей с локальными проблемами, без автоматического изменения каналов.

## Офлайн-PCAP
В PowerShell:
```powershell
.\PcapInspect.ps1 -Path 'D:\captured\wifi.pcap'
```
Импортируйте только принадлежащие вам или разрешённые записи. Эта команда **не** запускает радио-захват.

## Безопасность
Никакого обхода разрешений Windows, прямых обращений к прошивке, deauth, отправки кадров, доступа к чужому трафику, установки Npcap, Docker или новых обязательных зависимостей.

## Проверки
`tests/WifiV3.Tests.ps1`, существующие PowerShell-регрессии, Node Web Map и Windows GitHub Actions. Аппаратную поддержку Direct/monitor на ноутбуке пользователя CI проверить не может.
